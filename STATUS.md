## China auto-scraper — first promoted region (2026-08-20)

User asked for a system that "automatically scrapes China's publications and updates the database." Built the engine + promoted the first (largest) region, Xinjiang. Open as PR (branch `feat/china-auto-scraper`).

- **Source reality (verified):** the repo's China anchors came from a 2024 *annual* NEA press release (`nea.gov.cn/.../c.html`, published 2025-10-28) — not a feed. The authoritative *monthly* source (全国新能源消纳监测预警中心) was unreachable from the dev sandbox (geo/network). The reachable, structured, English backbone is **Ember "China Electricity Data"** (`ember-energy.org/data/china-electricity-data` → GCS `release_chn_subnational_generation_monthly.csv`, real per-province per-fuel monthly generation through 2026-06).
- **What the scraper does:** `scripts/refresh-china.ts` ingests that CSV, annualises the trailing-12-month generation per province+fuel, applies the **published NEA curtailment rate** (弃风率/弃光率 — transcribed from each loader's own `source` note, NOT invented), and writes `data/china-anchors.json` (the refreshed data store). `--dry-run` prints the delta without writing; fails non-zero if the fetch fails (no partial writes).
- **Honesty boundary (critical):** Ember CSV = *generation*, not curtailment. So the promotion is `live-domestic-anchored` (T1b): live-monthly generation anchor + published curtailment rate, with the 24h *shape* staying the modelled typical-profile. We do **NOT** claim `live` (T1a) hourly curtailment — no public Chinese source provides that, and claiming it would re-violate PR #812's contract. Parser is unit-tested offline against a saved fixture; the shape is faithful to the real bulletin schema.
- **Mechanism:** `src/lib/chinaParse.ts` `buildChinaRegionFromAnchor(regionId, fuel, peakHourUtc, fallbackAnnualTWh, fallbackNote)` — when `china-anchors.json` exists it promotes the region to T1b (`confidenceTier: "T1b-live-domestic-anchored"`, `sourceProvenance: "verified"`, `sourceStatus: "live"`); when absent it falls back to the loader's current `estimated` anchor (behavior unchanged until the store is generated). `china-anchors.json` currently holds **48 anchors** (latest month 2026-06).
- **First promotion:** `xinjiang-wind` + `xinjiang-solar` promoted `estimated` → `live-domestic-anchored`; `regions.ts` tiers + `golden/tier-counts.json` updated (T1b 26→28, T3 249→247, total 459 unchanged). Xinjiang's anchors are now 6.34 / 5.94 TWh from 2026 data (vs the old 2024 NEA 5.0 / 3.2). The remaining ~46 China `estimated` regions follow the identical pattern once their loaders call `buildChinaRegionFromAnchor` — mechanical, each a one-line swap; that is the follow-up push ("upgrade as many regions as possible").
- **Tests:** `tests/chinaParse.test.ts` (parser), `tests/refresh-china.test.ts` (buildAnchors + store reader), `tests/chinaRegion.test.ts` (promote-vs-fallback), `tests/data/xinjiang.test.ts` (promoted path). Full suite 1097 pass; all 4 CI gates pass.

## Tier-promotion survey (2026-08-02) — read before proposing T1 upgrades

Full sweep of all **274 T2/T3 regions** against `docs/methodology/live-data-paths.md`. **Every region at T1 is not achievable**, and the binding constraint is not engineering — it is Test 2: a Path-B rate only counts as T1 if the numerator is **published by the operator itself**. Failure mode 2 disqualifies Ember/IRENA-derived rates outright, because those are back-derived econometrically from generation, making the calculation a double-counted estimate.

Breakdown by blocker: **IRENA-sourced 79** (barred by failure mode 2, no feed exists) · **China NEA provinces 57** (no hourly provincial feed) · **US EIA BAs 19** · **Peru COES 12** (already Path B) · **India 13** · **Korea/Hawaii/misc ~9** · **long-tail single utilities ~90** (probed 12: 5 unreachable, 7 served HTML homepages, none machine-readable).

**US EIA balancing authorities — CLOSED, no promotion possible.** The loaders already fetch live hourly EIA-930 (verified: ~132,000 rows per BA, current to today). The only blocker is the rate. Researched 2026-08-02: **LBNL reports curtailment for the seven ISOs only** — its own figure caption reads `Sources: ERCOT, MISO, CAISO, NYISO, PJM, ISO-NE, SPP`, and the non-ISO West/Southeast buckets that appear elsewhere in the same report are explicitly dropped from the curtailment table. For solar, only CAISO and ERCOT report at all. So there is **no LBNL number for SOCO, PACE, PACW, PSCO, AZPS, SRP, IPCO, TEPC or WACM at any level of aggregation**. Checked each BA's own IRP/FERC/ESG filings too: the only figure found was Xcel/PSCO's Clean Energy Plan **5%–15% curtailment**, which is a forward-looking *modelling assumption* for a hypothetical future portfolio whose value depends purely on which docket you pick — it fails Test 2 (not a measurement) and would fail Test 3 (3× instability) regardless. Idaho Power's cited "PURPA curtailment" anchor appears to conflate curtailment with a *wind QF contract-renewal-rate* assumption and should be re-checked. **All 18 stay T2. Do not re-run this search.**

**India — the geoblock framing is partly wrong; Maharashtra is the real prize.** Probed 2026-08-02. First, a correction that invalidates the [#43](https://github.com/honeybeesquad/every-last-joule-dashboard/issues/43) relay premise: **`abed` shares this workstation's public IP** (Starlink, Christchurch) — it is not an independent vantage point, so it cannot test the Peru/COES "residential IP bypasses the block" hypothesis for India. That needs a genuinely separate egress. Second, **four of eight India `sourceUrl`s were dead domains** (NXDOMAIN at the registry — `msldc.mahavedha.com`, `apsldc.in`, `tnsldc.com`, `sldc.gujarat.gov.in`), not geoblocked; corrected in `regions.ts` this sweep to `mahasldc.in`, `sldc.aptransco.co.in`, `www.tantransco.org`, `www.sldcguj.com`. Third — the find: **`mahasldc.in` is fully reachable with no relay and publishes genuine official curtailment**, under Reports → REMC → Monthly Curtailment Reports: 75 monthly PDFs, each a *daily* wind+solar table with Max MW, Energy MU and free-text cause codes. That supports **`india-maharashtra` T3 → T1b** (daily cadence, not hourly, so T1b not T1a — same reasoning as Colombia). Needs a new loader: CodeIgniter CSRF handshake → `POST /report/fetchReports` → download `mr10_MMYYYY.pdf` → parse the daily table. Still blocked from NZ: Rajasthan, ERLDC, real-APSLDC, real-TNSLDC (TCP timeout), real-GSLDC (WAF 403). Karnataka (`kptclsldc.in`) is reachable but generation-only. The six `gen-re.cea.gov.in` regions are fully reachable and machine-readable but **generation-only**, so T3 is already their honest ceiling — though their committed CSVs haven't refreshed since **2026-05-07** despite the source being trivially reachable (housekeeping gap, not a tier issue).

**Maharashtra — SHIPPED 2026-08-03, T3 → T2 on MEASURED data.** The only promotion the survey found, and it is a magnitude correction as much as a tier move. `mahasldc.in` publishes Monthly Curtailment Reports (`mr10_MMYYYY.pdf`): daily wind+solar curtailed energy with the operator's own cause codes. Parsed **15 published months (2025-01 → 2026-06), 453 daily rows, 33.28 GWh total → ~26.8 GWh/yr**. The superseded loader applied an Ember India rate to CEA generation and emitted **0.101 TWh/30d (~1.23 TWh/yr)** — **~46× the measured figure**, and ~28× the worst single measured month. **Totals impact: Maharashtra effectively stops contributing to the global total.** Landed at **T2, not T1**, because MSLDC publishes monthly, lags 1–2 months, and skips months outright (2025-03, 2025-12, 2026-01, 2026-07 all 404 as at 2026-08-03) — measured data clears T2's bar comfortably, but no live-feed claim survives that cadence. Profile is flat 24/7: the source gives daily energy only, so no intraday shape is claimed. Refresh with `python3 scripts/fetch-msldc-curtailment.py` (needs `pdftotext`; nothing in CI fetches it — run on demand and commit the CSV). **Two bugs fixed alongside:** (1) `readStateSldcCurtailment` summed a trailing-N-day window but divided by the *total* row count, understating by `nRows/window` — a 453-row CSV read at 90 days came out 5× low; fixed at source and at all 12 India call sites. (2) The Maharashtra loader's no-CSV fallbacks emitted a T3-modelled shape, which would have contradicted the new `anchored` tier and tripped `ci:tier-coherence`; they now throw so `withFallback` degrades to the last-good T2 snapshot instead of silently reverting to the 46×-high estimate.

**The IRENA 79 are not a backlog.** They are correctly classified and structurally cannot move: IRENA publishes installed capacity, not measured curtailment, and using an IRENA-derived rate against a generation shape is barred by failure mode 2. Treat them as **done at the right tier**, not as pending work.

**Realistic ceiling: T1 + roughly 0–14 more regions, not 274.** Maharashtra — the one candidate this sweep found — landed at T2, not T1, once its publication cadence was checked. That is the pattern to expect: the constraint is what operators publish, not loader engineering.

## Worktree hygiene

- Rule: before creating any branch, run `git branch -a | grep <prefix>` and `gh pr list --state all --search <prefix>`. If a branch with similar name exists, ask the user before reusing it.
- Rule: stale worktrees are evidence to the next session that work is mid-flight. Tear them down when done — don't leave them around as breadcrumbs that mislead future Claudes.
- Run `git worktree list` to see current state. Most worktrees are dispatch artefacts from earlier phases; not all represent live work. If unsure whether a worktree is active, ask the user before touching its branch.
