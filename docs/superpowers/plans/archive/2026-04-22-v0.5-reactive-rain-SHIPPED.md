# v0.5: Sun-aligned globe, playback, pillars, and a much bigger live-data footprint

> **STATUS: SHIPPED — archived 2026-04-28.**
> Phase A landed in `f176098 feat(v0.5a): sun-aligned globe + playback clock + scrubbable timeline + pillars`. Phase B1–B4 landed across v1c–v1r plus the Africa/LatAm Pattern-D sweeps (PRs #17, #18). Theme system shipped in PR #14 (+ Phase 7 fixes in PR #21). Kept here for historical reference; do not treat as live work.

## Context

**Why this is being built:** the current v0 dashboard shows a static snapshot at current UTC hour. The terminator is a fixed screen-position gradient that has no relation to actual sun position. 10 of 17 regions have flat 24/7 profiles (static loaders), so even if we DID animate, those pillars wouldn't move. The visual story of "curtailment emerges as the sun passes over a region, then dissipates" is not told by the live dashboard.

Simon has also pushed back on accepting static-regions-stay-static as a defeat. We should push to get real data wherever possible, including via Playwright-Chrome bypass for Cloudflare-gated portals and Vercel's US build infrastructure for ERCOT's WAF.

v0.5 does three things:
1. **Visual: sun-aligned globe with pillars + playback.** Terminator tracks actual sub-solar longitude; pillars extend outward from each hotspot (height ∝ √GW); a playback clock advances UTC hour and a scrubbable timeline lets viewers pick any hour. Everything on the dashboard (headline %, stats, hotspot list, globe) scrubs together.
2. **Data: promote every statically-held region that has a live upstream.** AEMO per-state, Brazil NE plant clusters, ENTSO-E +France/Netherlands/Denmark, ERCOT sub-zone split, Norway live.
3. **Data: expand coverage to regions we don't currently touch.** Canada (IESO Ontario, AESO Alberta), Ireland (EirGrid), Peru (COES), South Africa (ESKOM), plus native ERCOT via Vercel and Chile via Playwright-Chrome.

**Intended outcome:** an interactive globe where a journalist sees the book's solar-block-following thesis visible in 10 seconds of auto-playback - pillars rising in Chile, California, Iberia as the sun moves overhead; flare pillars steady the whole time; the night side genuinely dim - and the region set is geographically complete enough that "global curtailment" isn't just a North-America-Europe claim with blank elsewhere.

## Design decisions (locked by Simon)

- **Option (b) pillars confirmed** (mockup at `mockups/pillar-concept.html`): glow underlay preserved, outward pillar added, height `3 + √GW × 48`.
- **Aggressive day/night contrast:** sun-side warm radial gradient peak `rgba(90,150,160,0.75)`, anti-solar hemisphere overlaid `rgba(0,0,0,0.55)` via `d3.geoCircle().center([antiSolarLng, 0]).radius(90)()`. Dot brightness `0.05 + fade × 0.12 + pow(sunlit, 0.7) × 0.85`.
- **Scrub sweeps the whole dashboard,** not just the globe. Headline %, stats, hotspot list, globe, all bound to one clock.
- **ERCOT: 66/34 West/East proportional split** in Phase B1 (render two hotspots now), native ERCOT attempted via Vercel US build in B2.
- **Norway: promote to live now** via Nord Pool / ENTSO-E Norway domain.
- **No synthetic-profile fallback accepted as a class** - we find live sources where possible. Only regions with genuinely no public source (China Sichuan/Xinjiang, Iceland, flare regions) get estimated treatment, and flare correctly stays flat.

## Implementation

### Phase A - sun-aligned globe + playback (4-5 days, ships first as its own PR)

Visual-only; doesn't require new data sources. Gives Simon the big visual win while data work runs in parallel.

**A.1: Port pillar + terminator rendering into `src/globe.js`**

Files:
- `src/globe.js` - replace the fixed-position day/night gradient (lines 82-95) with sun-aware rendering from the mockup. `sunLng = (12 - utcHour) × 15`, `sunLat = 0` (v0.5 flat-sun; axial tilt is v1 refinement). Day-side radial gradient centred on projected sub-solar point. Night-side shadow via `d3.geoCircle().center([antiSolarLng, 0]).radius(90)()` filled `rgba(0,0,0,0.55)`. Hotspot rendering: glow + core + outward pillar using vector from globe centre, `height = 3 + √gw × 48`, width 3px, base-to-tip gradient, tip glow.

**A.2: Reactive utcHour via Observable `Mutable`**

Files:
- `src/index.md` - introduce `const clock = Mutable(initialUtcHour)` from Observable Framework's reactive stdlib. The current imperative block that writes to `pct-readout`, `hashrate-readout`, etc., becomes a `function renderAt(hour) { ... }` called from a subscription (or a RAF loop reading `clock.value`).

**A.3: Playback controller**

New file:
- `src/components/clock.js` - `createClock(initialUtc)` returns `{ hour$, play, pause, setSpeed(speed), scrub(hour) }`. Internally a RAF loop advancing at `0.4 × speed` h/s (1× ≈ 60s per 24h).

**A.4: TimelineStrip**

New files:
- `src/components/timeline.js` - `mountTimeline(canvas, data, clock, onScrub)`. 24-value sparkline of `perHourAggregate(regionData, cbeci).map(r => r.totalGW)` (function already exists in `src/lib/calc.ts`). Draggable current-hour marker. Pointer events call `onScrub(hour)` setting the clock.
- `src/style.css` - `.timeline-strip` layout rules integrated into `.app-shell` grid.

**A.5: Play/pause/speed controls**

New file:
- `src/components/controls.js` - play button, speed chips 1×/2×/4×/8×, bound to the clock.

**A.6: Wire headline + hotspot list + globe to clock**

Every existing DOM write in `src/index.md` re-runs when `clock.hour$` changes. Globe's `update({ utcHour })` (already in `src/globe.js` lines 207-214) called each tick.

### Phase B - data comprehensively covers the world (10-14 days total, split into four work streams that can run in parallel)

Grouped so each sub-phase is shippable independently.

#### B1: Originally-scoped granularity and static→live promotions (3-4 days)

**AEMO per-state live:**
- New `src/data/aemo.json.ts` reading NEMWeb Dispatch_SCADA. Outputs 5 sub-regions (`aemo-nsw`, `aemo-vic`, `aemo-qld`, `aemo-sa`, `aemo-tas`).
- Remove `aemo` from `src/data/statics.json.ts`.
- Update `src/lib/regions.ts` with 5 new entries (lat/lon at each state's wind-farm cluster centroid).

**Brazil NE plant clustering:**
- New `src/lib/brazil-clusters.ts` with `id_ons` prefix → cluster id mapping (`brazil-ceara`, `brazil-rn`, `brazil-bahia`, `brazil-piaui`, `brazil-pernambuco`). 3-5 clusters, manually curated from ONS plant registry.
- `src/data/brazil-ne.json.ts` aggregates per cluster instead of single total. Output `Record<string, RegionData>`.

**ENTSO-E +France +Netherlands +Denmark-West:**
- `src/data/entsoe.json.ts` - extend `ZONES` with:
  - `france` domain `10YFR-RTE------C` psrType B19 rate 0.03
  - `netherlands` domain `10YNL----------L` psrType B16 rate 0.04
  - `denmark-west` domain `10Y1001A1001A65H` psrType B19 rate 0.04
- Rates are best-guess; tune when we have test-run data.

**ERCOT 66/34 split:**
- `src/data/ercot.json.ts` emits two region objects: `ercot-west` (66% of each hourly value, lat/lon 33.5/-102) and `ercot-east` (34%, lat/lon 31.8/-99.9). Output `Record<string, RegionData>`.
- Methodology note in `docs/data-source-log.md`: book cites West+Panhandle = 5.3 of ERCOT's 8 TWh 2024 curtailment.

**Norway live:**
- New `src/data/norway.json.ts` via Nord Pool hourly or ENTSO-E NO-zone endpoints (`10YNO-4--------9` for N. Norway zone 4). Calibration rate ~0.06.
- Remove from `src/data/statics.json.ts`.

#### B2: Hard-unlock attempts (3-4 days)

**ERCOT native via Vercel build infrastructure:**
- `src/data/ercot-native.json.ts` implementing the ROPC OAuth2 flow that earlier tests proved works: POST to `https://ercotb2c.b2clogin.com/.../oauth2/v2.0/token` with `ERCOT_USERNAME` + `ERCOT_PASSWORD` + `ERCOT_API_KEY` (all three already in Vercel env). Retrieve bearer token, call `https://api.ercot.com/api/public-reports/np6-345-cd/act_sys_load_by_wzn` (or similar dispatch-down endpoint) with both headers.
- Earlier blocker was Incapsula WAF blocking NZ IPs. Vercel build runs in US infrastructure, should pass.
- If it works: replaces EIA-based proxy as primary ERCOT source; EIA stays as fallback via `lib/resilient.ts::withFallback`.
- If it fails in Vercel's US IP: document the reason, stay on EIA proxy, flag for v1.

**Chile Atacama via Playwright-Chrome in GitHub Actions:**
- Cloudflare challenge persists even with UA spoofing (confirmed from our probe). Requires a real Chrome with JS execution.
- Install `playwright` as a dev dependency. New `src/data/atacama-chile.json.ts` uses playwright to load `https://www.coordinador.cl/reportes-y-estadisticas/` (and whatever specific data pages COES publishes), wait for Cloudflare pass, extract curtailment data from the rendered DOM.
- Significant: adds a headed-browser step to every Vercel build. Build time goes up ~30s. Worth testing in a preview branch first.
- Alternative path if Vercel doesn't allow playwright in build: run a daily GitHub Actions job that does the scrape, commits the result to `data/snapshots/last-good/atacama-chile.json`, and the Vercel build just reads from that committed file. Cleaner separation.

**Flag:** B2 is the riskiest work stream; either of these could fall through and we'd fall back to current state (EIA proxy for ERCOT, published-annual for Chile). Both attempts get a hard timebox - if a worker hasn't got a working fetch by day 2, stop and fall back.

#### B3: New region coverage via accessible public endpoints (4-5 days)

Each is a new loader following the established `Pattern A` (live sub-hourly) from the plan doc.

**Canada Ontario (IESO):**
- `src/data/iseo-ontario.json.ts` parses the HTML directory at `http://reports.ieso.ca/public/GenOutputCapability/` (returns 200 from NZ, 90KB of listings).
- Wind curtailment derivable from difference between max-capacity and actual-output columns in the XML reports. Calibration rate needed - IESO published ~1-2 TWh 2024 wind curtailment as an order-of-magnitude anchor.

**Canada Alberta (AESO):**
- `src/data/aseo-alberta.json.ts` parses the CSD report at `http://ets.aeso.ca/ets_web/ip/Market/Reports/CSDReportServlet` (200 from NZ, 30KB HTML table).
- Alberta has less wind curtailment historically but the new oversupply regime since 2023 makes it worth including.

**Ireland (EirGrid):**
- `src/data/ireland-eirgrid.json.ts` scrapes the public dashboard at `https://www.eirgridgroup.com/how-the-grid-works/renewables/` (200, HTML).
- Ireland has high wind penetration; SNSP curtailment is ~5-7% of wind, well-documented.

**Peru (COES-SINAC):**
- `src/data/peru-coes.json.ts` parses `https://www.coes.org.pe/Portal/portalinformacion/generacion` (200, Spanish HTML dashboard).
- Small grid but growing solar from Atacama-adjacent regions; feeds the Latin-American narrative.

**South Africa (ESKOM):**
- `src/data/south-africa-eskom.json.ts` parses `https://www.eskom.co.za/dataportal/` (200, 126KB HTML dashboard).
- Includes load-shedding and renewable-generation series; wind curtailment is low but meaningful during load-shedding windows.

Each adds an entry to `src/lib/regions.ts` with accurate lat/lon, updates `tests/regions.test.ts` count, is wrapped in `lib/resilient.ts::withFallback`.

#### B4: Best-guess time-of-day profiles for the few regions with no public hourly source (1 day)

Only Sichuan, Xinjiang, and Iceland fall here. Flare regions stay flat.

New file:
- `src/lib/typical-profiles.ts` - `solarProfile(localPeakUTC, annualTWh)` (Gaussian bump σ=2h, scaled), `hydroProfile(annualTWh)` (near-flat, hydro is monthly-seasonal not hourly), `windProfile(localPeakUTC, annualTWh)` (broad overnight).

Modifications:
- `src/data/statics.json.ts` - Sichuan uses `hydroProfile` (near-flat, still correct), Xinjiang uses `solarProfile` (morning peak given UTC+8 sub-solar at UTC 04-06), Iceland uses `hydroProfile`.
- `docs/known-limitations.md` - new section: "Sichuan, Xinjiang, and Iceland use typical daily shapes scaled to published annual totals. The shapes reflect each region's dominant fuel type; actual hour-by-hour values are not measured. Flare regions correctly stay flat because flare IS 24/7 base load. v1 will upgrade China and Iceland to measured hourly data where possible."
- `src/methodology.md` - surface this to user-facing methodology page.

## Execution order and shipping

1. **Phase A ships first** as its own PR. Visual unlock is valuable even at current 17 regions; Simon sees progress fast.
2. **Phase B1 + B3 run in parallel** (both safe, known-accessible endpoints). Each new loader is its own PR, dispatch-one-at-a-time to Codex/Gemini.
3. **Phase B2 runs with timeboxes.** ERCOT native: 1-day spike, succeed-or-fall-back. Chile Playwright: 2-day spike, succeed-or-use-GH-Actions-commit-pattern or fall back to static.
4. **Phase B4 ships last** after live regions are landed so the estimated-profile language can frame-around them.
