# CI coherence — tier alignment, tally drift, docs drift

Date: 2026-04-25 · Owner: Claude (council finding S4) · Status: design — implementation queued for Codex (CODEX-6) · Paper section: Code Availability §6.

## Why this exists

The 5-agent council (Software Architect + Code Reviewer + Reality Checker, converging) flagged three failure modes the current CI does not catch:

1. **Tier drift.** A loader's emitted `confidenceTier` field can fall out of sync with `regions.ts.tier` without anyone noticing. The snapshot validator checks the tier is *valid*, not that it *matches the source-of-truth declaration*. A reviewer pulling `regions.ts` and the snapshot would see the inconsistency; CI does not.

2. **Tally drift.** `scripts/tally-tiers.ts` is the authoritative count for paper §4 / Figure 4 / CHANGELOG. Today CI prints the output but doesn't assert it. A loader change can shift the T1/T2/T3 counts silently — the kind of thing that surfaces only when a reviewer questions a figure caption mid-revise.

3. **Docs drift.** `docs/validation/*.md` is generated by `scripts/validation/build_region_docs.py` and partly hand-enriched. After every code change that affects a region's tier, kind, or backfill year-count, the docs need regeneration. There's no enforcement; today the docs are kept in sync by Claude memory, which is not a control.

Three small CI checks close all three gaps. They are cheap (sub-second to seconds), deterministic, and re-use existing scripts. The implementation is mechanical; the design below is what Codex needs to land it correctly on the first try.

## Design constraints (locked)

1. **No new dependencies.** Use Python stdlib + Node + the scripts that already exist.
2. **Cheap.** Each check finishes in < 5s on a typical runner. Cumulative add ≤ 10s to CI wall-clock.
3. **Reversible.** Every check has an obvious "intentional change" path: update a golden file or commit regenerated docs in the same PR.
4. **Don't fight existing patterns.** The validate-snapshots step already walks every snapshot. Add to its loop where natural; don't duplicate iteration.

## Check 1 — Tier coherence

### What it does

For every region in `regions.ts`:
- Read `data/snapshots/last-good/<region_id>.json` (the committed snapshot).
- Compute the *expected* `confidenceTier` by passing `regions.ts.tier` and any inferred `profileKind` through `deriveTier()` (the same function the loaders use).
- Assert `snapshot.confidenceTier === expected`.

This catches:
- A loader was switched from live to static fallback but the snapshot still says `"live-tso"`.
- A typical-profile region was upgraded to live but the static spec still emits `"modelled"`.
- Manual edits to a snapshot that contradict `regions.ts`.

### Where it lives

A new TypeScript file: `scripts/validate-tier-coherence.ts`. Wired into `npm run validate` (existing snapshot validator already runs there) — added as a second pass.

Pseudo-code:

```typescript
// scripts/validate-tier-coherence.ts
import { REGIONS } from "../src/lib/regions.js";
import { deriveTier } from "../src/lib/uncertainty.js";
import { STATIC_PROFILE_KIND } from "./tally-tiers.js"; // export the map

const failures: string[] = [];
for (const region of REGIONS) {
  const snapPath = `data/snapshots/last-good/${region.id}.json`;
  if (!existsSync(snapPath)) continue;  // no snapshot, skip
  const snap = JSON.parse(readFileSync(snapPath, "utf-8"));

  const profileKind = STATIC_PROFILE_KIND[region.id];  // undefined for live/flare
  const expected = deriveTier({ regionTier: region.tier, profileKind });

  if (snap.confidenceTier !== expected) {
    failures.push(
      `${region.id}: snapshot.confidenceTier="${snap.confidenceTier}" but regions.ts.tier="${region.tier}" → expected="${expected}"`
    );
  }
}
if (failures.length) {
  console.error("Tier-coherence failures:");
  failures.forEach((f) => console.error("  " + f));
  process.exit(1);
}
console.log(`✓ Tier-coherence: ${REGIONS.length} regions consistent`);
```

### Tooling change

Move `STATIC_PROFILE_KIND` from a private const inside `scripts/tally-tiers.ts` to a shared module, e.g. `scripts/lib/static-profile-kinds.ts`. Both `tally-tiers.ts` and `validate-tier-coherence.ts` import it. (One source of truth for static kind metadata.)

### Edge cases

- **Backfill-only aggregate regions** (`iso-ne`, `nyiso`) — these are NOT in `regions.ts` but DO have snapshots. Skip them; they're documentary aggregates, not loader outputs.
- **Probe-only regions** (`iran`, `uae`, `saudi-solar`) — they declare `tier: "static"` and resolve through typical profile. `STATIC_PROFILE_KIND` must include them. Verify before landing.
- **Split children** (`gb-scotland`, `gb-england-wales`) — these don't have committed snapshots; the parent (`north-sea`) does, and the split is runtime. Skip if no snapshot exists. The check is correct because the parent's tier matches; children inherit at runtime.

### Done criteria

- `npm run validate:tiers` (new script in `package.json`) exits 0 on a clean tree.
- Add a regression test: temporarily flip `regions.ts.tier` for one region, run the validator, assert non-zero exit and the failure message names the region.

## Check 2 — Tally golden file

### What it does

Captures the deterministic output of `scripts/tally-tiers.ts` to a committed file `tests/__golden__/tally-tiers.txt`. CI runs the tally, normalises whitespace + timestamps, diffs against the golden file. Any unintended change fails the build with a clear diff.

### Where it lives

- New file: `tests/__golden__/tally-tiers.txt` (committed).
- New script: `scripts/check-tally-golden.sh` or `.ts`. CI invokes via `npm run check:tally`.

Pseudo-code:

```bash
#!/usr/bin/env bash
# scripts/check-tally-golden.sh
set -euo pipefail
GOLDEN="tests/__golden__/tally-tiers.txt"
ACTUAL=$(npm run --silent tally:tiers)
DIFF=$(diff <(echo "$ACTUAL") "$GOLDEN" || true)
if [[ -n "$DIFF" ]]; then
  echo "Tally drift detected. Run 'npm run tally:tiers > $GOLDEN' to update if intentional."
  echo "$DIFF"
  exit 1
fi
echo "✓ Tally matches golden"
```

### Update path

When a region is added/removed/retiered, the developer:
1. Makes the code change.
2. Runs `npm run tally:tiers > tests/__golden__/tally-tiers.txt`.
3. Commits both the code and the golden file in the same PR.

### Edge cases

- **Deterministic ordering** required. Verify `tally-tiers.ts` outputs regions in a stable sort (by `region_id` alphabetical). If not currently stable, add a sort before printing.
- **No timestamps in output**. Verify the script doesn't print "as of YYYY-MM-DD" or similar; if it does, redirect through `sed` to strip timestamp lines before diff.
- **Cross-platform line endings**. CI runs Linux; developers may be on macOS. `diff` handles this fine but be aware.

### Done criteria

- Initial golden file committed reflecting current state (T1: N, T2: N, T2-flare: N, T3: N).
- Synthetic regression: change one region's tier, run check, assert non-zero exit.

## Check 3 — Docs drift

### What it does

Adds a `--check` flag to `scripts/validation/build_region_docs.py`. With `--check`, the script:
1. Regenerates all `docs/validation/*.md` content in memory.
2. Diffs each against the committed file on disk.
3. Excludes the `Last updated:` line from the diff (line 3 of every file follows the pattern `Last updated: YYYY-MM-DD · ...`).
4. Excludes the `Last generated:` line from `docs/validation/README.md`.
5. Exits 0 if no diffs (other than the excluded lines), 1 if any region MD has drifted.

### Why excluding the date line is correct

The `Last updated:` line is intentionally regenerated to reflect when the doc was last touched. Drift in that field alone is not a content drift — it's just a clock tick. Excluding it from the comparison lets developers regenerate-and-commit on a different day without spurious CI noise.

### Implementation sketch

```python
# scripts/validation/build_region_docs.py
import argparse, difflib

def main() -> int:
    ap = argparse.ArgumentParser()
    ap.add_argument("--check", action="store_true",
                    help="Exit non-zero if regenerated content differs from committed.")
    args = ap.parse_args()

    regions = parse_regions_ts()
    anchors = load_anchors()
    # ... existing region/aggregate setup ...

    if args.check:
        return _check_drift(regions, anchors)
    # ... existing write path ...

def _check_drift(regions, anchors) -> int:
    drift_count = 0
    for r in regions:
        new_doc = build_region_doc(r, anchors)
        out = VALIDATION_DIR / f"{r['id']}.md"
        if not out.exists():
            print(f"DRIFT: {r['id']}.md missing on disk", file=sys.stderr)
            drift_count += 1
            continue
        old_doc = out.read_text(encoding="utf-8")
        if _normalised(new_doc) != _normalised(old_doc):
            print(f"DRIFT: {r['id']}.md differs from regenerated content", file=sys.stderr)
            diff = list(difflib.unified_diff(
                _normalised(old_doc).splitlines(keepends=True),
                _normalised(new_doc).splitlines(keepends=True),
                fromfile=f"committed/{r['id']}.md",
                tofile=f"regenerated/{r['id']}.md",
                n=2,
            ))
            sys.stderr.writelines(diff[:30])  # cap diff size per region
            drift_count += 1
    if drift_count:
        print(f"\n{drift_count} validation MDs drifted. Run "
              f"`python3 scripts/validation/build_region_docs.py` to regenerate.",
              file=sys.stderr)
        return 1
    print(f"✓ No docs drift across {len(regions)} regions")
    return 0

def _normalised(text: str) -> str:
    """Strip 'Last updated:' / 'Last generated:' lines for diff comparison."""
    return "\n".join(
        line for line in text.splitlines()
        if not line.startswith(("Last updated:", "Last generated:"))
    )
```

### Edge cases

- **Hand-enriched sections.** `build_region_doc` already calls `_extract_enriched_sections` to preserve the prose Simon/Claude/Gemini wrote. Drift check is correct because the regen path uses the same extraction. If a developer edits an enriched section, the regenerated doc will contain that edit, and CI passes (no drift). If a developer edits a *generated* section by hand, CI catches it — that's the intent.
- **README.md (the validation index).** Same `--check` logic should apply to it. Add a step that builds the index and diffs against committed.
- **`scripts/validation/__pycache__`** must be gitignored (already is). Confirm.
- **File missing on disk.** Treat as drift (non-zero exit, message names the missing region).

### Done criteria

- `python3 scripts/validation/build_region_docs.py --check` exits 0 on a clean tree.
- Synthetic regression: edit one validation MD's body to change a generated section (e.g. flip a Δ% value in the table), run check, assert non-zero exit and clear diff in stderr.
- CI step `Validate docs drift` runs in < 3 seconds on a clean tree.

## CI integration

Update `.github/workflows/ci.yml` to add three steps after the existing `validate` step:

```yaml
- name: Validate tier coherence
  run: npm run validate:tiers

- name: Validate tally golden file
  run: npm run check:tally

- name: Validate docs drift
  run: python3 scripts/validation/build_region_docs.py --check
```

Run order: typecheck → test → validate (snapshots) → validate:tiers → check:tally → check:docs. Each is independent; failure at any step fails the run.

`package.json` scripts to add:

```json
{
  "scripts": {
    "validate:tiers": "tsx scripts/validate-tier-coherence.ts",
    "check:tally": "bash scripts/check-tally-golden.sh",
    "check:docs": "python3 scripts/validation/build_region_docs.py --check"
  }
}
```

## Failure-mode table — what each check catches

| Failure mode | Caught by | Surfaced as |
|---|---|---|
| Loader emits wrong `confidenceTier` for its `regions.ts` declaration | Check 1 | `<region>: snapshot.confidenceTier="X" but regions.ts.tier="Y" → expected="Z"` |
| Region added to `regions.ts` but no snapshot generated | Check 1 (skipped, but) Check 2 will diff | tally golden differs |
| Region removed from `regions.ts` but snapshot still committed | Check 1 (no failure on its own; snapshot still validates schema-wise) | Check 2 tally differs |
| Tier counts shifted because of a loader change | Check 2 | golden-file diff with line-by-line counts |
| Validation MD edited by hand in a generated section | Check 3 | `DRIFT: <region>.md differs from regenerated content` + unified diff |
| `external-anchors.json` updated but MDs not regenerated | Check 3 | drift surfaces in "Published anchors" section |
| New backfill year landed but MD year-count not updated | Check 3 | drift in "Multi-year backfill annual totals" table |
| `regions.ts` typo or duplicate region id | None of these (would surface earlier in `parse_regions_ts`) | (out of scope) |

## What this does NOT cover

- **Loader correctness.** Whether a loader's emitted curtailment value is *correct* is the snapshot validator's job (envelope, schema). This design is purely about coherence between source-of-truth declarations and downstream artefacts.
- **External-anchors validity.** That's S1 + the `check_anchors.py` script designed in `anchor-schema-v2.md`. Could be added as a 4th step here once GEMINI-3 lands.
- **Cross-region consistency** (e.g. all ENTSO-E zones use the same calibration approach). Out of scope; would require a separate audit script.
